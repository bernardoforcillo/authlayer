`store/drops` declares **`package dropsstore`**, and it is the production
backend: four stores over their own tables, generic over your container and
member types, deriving columns from `drop:` struct tags.

## The wiring, in full

This is the one place production wiring is written down, so it is written out
with imports included — because two of the packages involved are both named
`stdlib` and one of them is imported only for its side effect.

{/* verify:import */}
```go
import (
	"context"
	"database/sql"
	"fmt"

	"github.com/bernardoforcillo/drops/pg"
	"github.com/bernardoforcillo/drops/stdlib" // used BY NAME: wraps a *sql.DB
	_ "github.com/jackc/pgx/v5/stdlib"         // BLANK: registers the "pgx" driver

	"github.com/bernardoforcillo/authlayer/auth"
	"github.com/bernardoforcillo/authlayer/invite"
	"github.com/bernardoforcillo/authlayer/org"
	dropsstore "github.com/bernardoforcillo/authlayer/store/drops"
)
```

{/* verify:decl */}
```go
func newOrgService(ctx context.Context, dsn string) (*org.Service, error) {
	sqlDB, err := sql.Open("pgx", dsn) // "pgx" comes from the blank import above
	if err != nil {
		return nil, err
	}
	db := pg.New(stdlib.New(sqlDB))                        // a drops handle
	st := dropsstore.New[org.Organization, org.Member](db) // the scope.Store
	if err := st.CreateSchema(ctx); err != nil {           // or use your own migrations
		return nil, err
	}
	return org.New(org.NewAccess(nil), st), nil
}
```

<Warning>
`drops/stdlib` is the adapter that turns a `database/sql` handle into a drops
driver. `pgx/v5/stdlib` is the pgx driver itself, blank-imported so that its
`init` registers the name `sql.Open` is given.

**Neither is optional, and only one of them can own the identifier `stdlib`.**
</Warning>

`sql.Open` does not connect, so everything up to `CreateSchema` builds without a
database. That is exactly how far this page's own executed sample goes:

{/* verify:main */}
```go
sqlDB, err := sql.Open("pgx", "postgres://user:pass@localhost:5432/app?sslmode=disable")
fmt.Println("open:", err)

db := pg.New(stdlib.New(sqlDB))
scopeStore := dropsstore.New[org.Organization, org.Member](db)
authStore := dropsstore.NewAuthStore(db)
inviteStore := dropsstore.NewInviteStore(db)
identityStore := dropsstore.NewIdentityStore(db) // optional: external identities

orgSvc := org.New(org.NewAccess(nil), scopeStore)
authSvc := auth.New(authStore, auth.WithIdentityStore(identityStore))
inviteSvc := invite.New(orgSvc.Service, inviteStore)
fmt.Println("three services, four stores:",
	orgSvc != nil, authSvc != nil, inviteSvc != nil, identityStore != nil)

_ = newOrgService // the function above; calling it needs a live database
```

```
open: <nil>
three services, four stores: true true true true
```

## Six stores, six sets of tables

| Constructor | Port | Default tables |
|---|---|---|
| `New[C, M](db, opts...)` | `scope.Store` | `organizations`, `organization_members`, `organization_roles` |
| `NewAuthStore(db, opts...)` | `auth.Store` | `users`, `sessions`, `verifications` |
| `NewInviteStore(db, opts...)` | `invite.Store` | `organization_invites`, `organization_invite_links` |
| `NewAPIKeyStore(db, opts...)` | `apikey.Store` | `service_accounts`, `api_keys` |
| `NewOAuthStore(db, opts...)` | `oauth.Store` | `oauth_clients`, `oauth_grants`, `oauth_codes`, `oauth_device_authorizations`, `oauth_refresh_tokens` |
| `NewIdentityStore(db, opts...)` | `auth.IdentityStore` — [optional](/oauth/overview) | `identities` |

Each has its own `CreateSchema` and its own `Schema()`. **No foreign keys are
declared between stores** — not to a users table from the RBAC side, which
authlayer does not own, not between the three auth tables, and not from
`identities` to `users` either. That last one is also forced: the auth store
may be an entirely different backend. Every foreign key in the package is
*inside* a store: `api_keys.service_account_id` references
`service_accounts(id)` with `ON DELETE CASCADE`, and the five OAuth tables
reference one another the same way, because in each case both ends are owned
by the same store — see [the schema](/storage/schema#the-service-account-tables).

{/* verify:main */}
```go
fmt.Println(dropsstore.NewSchema[org.Organization, org.Member]().Containers.Name())
fmt.Println(dropsstore.NewAuthSchema().Users.Name())
fmt.Println(dropsstore.NewInviteSchema().Links.Name())
fmt.Println(dropsstore.NewIdentitySchema().Identities.Name())
fmt.Println(dropsstore.NewOAuthSchema().RefreshTokens.Name())
```

```
organizations
users
organization_invite_links
identities
oauth_refresh_tokens
```

## Renaming tables

A different scope needs only a set of names:

{/* verify:main */}
```go
teams := dropsstore.New[org.Organization, org.Member](db, dropsstore.WithNames(
	dropsstore.Names{
		Containers: "teams",
		Members:    "team_members",
		Roles:      "team_roles",
	}))
fmt.Println("renamed:", teams.Schema().Containers.Name())
```

```
renamed: teams
```

`WithAuthNames(AuthNames{...})`, `WithInviteNames(InviteNames{...})` and
`WithIdentityNames(IdentityNames{...})` do the same for the other three — reach
for the first if `users` is already taken in your database.

## Column derivation

Columns come from the `drop:` tags on your types.

<Warning>
Field types are restricted to `string`, `time.Time`, `*time.Time`, `[]byte`,
`int` or `int32` — or a named type over `string`, `int` or `int32`. Anything
else, **any other pointer included**, panics at construction with the column and
the type named.

`*time.Time` is the one nullable shape: it drops the `NOT NULL` and a nil
pointer is written as the SQL `NULL` keyword rather than a parameter. It is what
`email_verified_at`, `rotated_at` and `last_used_at` are.

A field with no `drop:` tag (or `drop:"-"`) is not persisted. Your container
type must tag `id`, `owner_id`, `created_at` and `updated_at`, and your member
type `container_id`, `user_id`, `role_key` and `joined_at` — embedding
`scope.ContainerBase` and `scope.MemberBase` does that for you, and a type that
misses one is **rejected at construction** rather than at the first query.
</Warning>

## What `CreateSchema` does, and does not

<Columns cols={2}>
  <Card title="Idempotent" icon="rotate">
    Every statement it issues is safe to re-run. Tables are
    `CREATE TABLE IF NOT EXISTS`, indexes `CREATE INDEX IF NOT EXISTS`, and the
    constraints a `CREATE TABLE` cannot carry go out as guarded `ALTER TABLE`s.
  </Card>
  <Card title="Additive only" icon="triangle-exclamation">
    It only ever adds what is **missing**. A table that already exists with
    different columns or constraints is left as it stands: `CreateSchema` will
    **not migrate an existing schema forward**.
  </Card>
</Columns>

`st.Schema()` exposes the table definitions if you would rather generate the DDL
and run it through your own migration tool.

## Versioned migrations with drops' `TreeMigrator`

Every store describes its schema as nodes for drops' `pg.TreeMigrator`, so
authlayer's tables are migrated by the same tool, and tracked in the same
place, as your own:

{/* verify:skip needs a live PostgreSQL *pg.DB and stores built over it; the identical migrator run is executed against a real server by store/drops' TestMigrationsBuildTheSameSchemaAsCreateSchemaLive */}
```go
m := pg.NewTreeMigrator(db)
dropsstore.AddMigrations(m, authStore, rbacStore, oauthStore, inviteStore)
// your own migrations go on m too, on their own branch
if err := m.Up(ctx); err != nil {
    log.Fatal(err)
}
```

Each store contributes a chain on the `authlayer` branch: `authlayer-<first
table>-001_tables` (tables, composite constraints and the 0.3.1 indexes) and,
where it has any, `authlayer-<first table>-002_indexes` (the indexes added
since). IDs and statements follow the table names and ID options the store was
built with, so a second `Store` under `WithNames` gets its own chain. The audit
and consent stores contribute a single `-001` step that replays their DDL.

- **Adopting an existing database is safe.** Every step is idempotent, so a
  database `CreateSchema` already populated applies cleanly and gains only what
  it is missing.
- **Table steps cannot be rolled back.** They have no `Down`, because dropping a
  table is data loss. Index steps do, and `DownTo` drops exactly the indexes
  they created.
- **Later releases add steps, never edit these.** A new index arrives as a new
  node whose parent is the previous one.
- **The steps are Go, not SQL text,** so the migrator's tamper check does not
  cover them. They are generated from the same definitions `CreateSchema` uses.

## Adding the indexes with your own SQL migrations

If you do not use the `TreeMigrator`, releases after 0.3.1 add indexes. Re-running `CreateSchema` creates them on
tables that already exist (every one is `CREATE INDEX IF NOT EXISTS`), but if
you own these tables in your own migrations, run the statements below instead.
On a large table use `CONCURRENTLY`, which cannot run inside a transaction
block. Skip the lines for stores you do not use, and adjust names if you passed
`WithNames` or its siblings.

```sql
-- RBAC: every authorization guard resolves a user's memberships by user_id
CREATE INDEX CONCURRENTLY IF NOT EXISTS organization_members_user_id_idx ON organization_members (user_id);

-- auth: list/revoke a user's sessions; PurgeExpired range deletes
CREATE INDEX CONCURRENTLY IF NOT EXISTS sessions_user_id_idx ON sessions (user_id);
CREATE INDEX CONCURRENTLY IF NOT EXISTS sessions_expires_at_idx ON sessions (expires_at);
CREATE INDEX CONCURRENTLY IF NOT EXISTS verifications_expires_at_idx ON verifications (expires_at);
CREATE INDEX CONCURRENTLY IF NOT EXISTS passkey_challenges_expires_at_idx ON passkey_challenges (expires_at);
CREATE INDEX CONCURRENTLY IF NOT EXISTS trusted_devices_expires_at_idx ON trusted_devices (expires_at);

-- invitations
CREATE INDEX CONCURRENTLY IF NOT EXISTS organization_invite_links_container_id_idx ON organization_invite_links (container_id);
CREATE INDEX CONCURRENTLY IF NOT EXISTS organization_invite_links_expires_at_idx ON organization_invite_links (expires_at);
CREATE INDEX CONCURRENTLY IF NOT EXISTS organization_invites_expires_at_idx ON organization_invites (expires_at);

-- service accounts
CREATE INDEX CONCURRENTLY IF NOT EXISTS api_keys_expires_at_idx ON api_keys (expires_at);
CREATE INDEX CONCURRENTLY IF NOT EXISTS api_keys_revoked_at_idx ON api_keys (revoked_at);

-- OAuth
CREATE INDEX CONCURRENTLY IF NOT EXISTS oauth_grants_expires_at_idx ON oauth_grants (expires_at);
CREATE INDEX CONCURRENTLY IF NOT EXISTS oauth_grants_revoked_at_idx ON oauth_grants (revoked_at);
CREATE INDEX CONCURRENTLY IF NOT EXISTS oauth_codes_expires_at_idx ON oauth_codes (expires_at);
CREATE INDEX CONCURRENTLY IF NOT EXISTS oauth_device_authorizations_expires_at_idx ON oauth_device_authorizations (expires_at);
CREATE INDEX CONCURRENTLY IF NOT EXISTS oauth_refresh_tokens_expires_at_idx ON oauth_refresh_tokens (expires_at);
```

Releases after 0.3.1 also add composite foreign keys that guard repeated
columns (see [conventions](/storage/conventions#normalization)). Each needs a
`UNIQUE` on its parent first. Add the key `NOT VALID`, which enforces it for new
rows without scanning the table, then validate it once the data allows:

```sql
ALTER TABLE service_accounts ADD CONSTRAINT service_accounts_id_container_id_key UNIQUE (id, container_id);
ALTER TABLE api_keys ADD CONSTRAINT api_keys_service_account_id_container_id_fkey
  FOREIGN KEY (service_account_id, container_id) REFERENCES service_accounts (id, container_id)
  ON DELETE CASCADE NOT VALID;
ALTER TABLE api_keys VALIDATE CONSTRAINT api_keys_service_account_id_container_id_fkey;

ALTER TABLE oauth_grants ADD CONSTRAINT oauth_grants_id_client_id_key UNIQUE (id, client_id);
ALTER TABLE oauth_codes ADD CONSTRAINT oauth_codes_grant_id_client_id_fkey
  FOREIGN KEY (grant_id, client_id) REFERENCES oauth_grants (id, client_id) ON DELETE CASCADE NOT VALID;
ALTER TABLE oauth_codes VALIDATE CONSTRAINT oauth_codes_grant_id_client_id_fkey;
ALTER TABLE oauth_refresh_tokens ADD CONSTRAINT oauth_refresh_tokens_grant_id_client_id_fkey
  FOREIGN KEY (grant_id, client_id) REFERENCES oauth_grants (id, client_id) ON DELETE CASCADE NOT VALID;
ALTER TABLE oauth_refresh_tokens VALIDATE CONSTRAINT oauth_refresh_tokens_grant_id_client_id_fkey;
```

`VALIDATE` fails, naming the offending constraint, if a row already disagrees
with its parent; fix or delete those rows and run it again.

The `expires_at` indexes serve the `PurgeExpired` janitors. Those now delete in
batches of 5000 rows per statement instead of one unbounded `DELETE`, so a long
expired tail no longer holds its locks for the whole purge. `PurgeExpired` on the
OAuth store is unchanged: it is one transaction because it cascades from grants.

<Note>
One thing it does self-heal: the `UNIQUE` constraint on `users.email` is
declared **both** inline and as a named `ALTER TABLE`, because
`CREATE TABLE IF NOT EXISTS` is a no-op against a table that already exists. The
guarded `ALTER` is what repairs a users table created by an older version or by
hand — proven live, after a run against such a table left two rows sharing one
address and `CreateUser` returning nil for the duplicate.
</Note>

## Id column types

Every id authlayer mints lands in a `uuid` column **by default**. If you
override `WithIDGenerator`, you need the matching option on each store, and
`store/memory` will not warn you — see [Ids](/concepts/ids).

| Store | Library ids | User ids |
|---|---|---|
| `New` | `WithTextLibraryIDs()` | `WithTextUserIDs()` |
| `NewInviteStore` | `WithInviteTextLibraryIDs()` | `WithInviteTextUserIDs()` |
| `NewAPIKeyStore` | `WithAPIKeyTextLibraryIDs()` — moves `service_account_id` too | `WithAPIKeyTextUserIDs()` |
| `NewOAuthStore` | `WithOAuthTextLibraryIDs()` — moves `client_id`, `grant_id`, `family_id`, `container_id`, `service_account_id` too | `WithOAuthTextUserIDs()` |
| `NewAuthStore` | `WithAuthTextLibraryIDs()` — moves **all five** columns | none, deliberately |
| `NewIdentityStore` | `WithIdentityTextLibraryIDs()` — moves **both** columns | none, deliberately |

Pass `WithIdentityTextLibraryIDs()` **alongside** `WithAuthTextLibraryIDs()`:
`identities.user_id` references `users.id`, so leaving one `uuid` while the other
went `text` fixes nothing and fails the first sign-in with the very error the
option was added to remove.

{/* verify:main */}
```go
textIDs := dropsstore.New[org.Organization, org.Member](db,
	dropsstore.WithTextLibraryIDs(), dropsstore.WithTextUserIDs())
fmt.Println("options compose:", textIDs != nil)
```

```
options compose: true
```

`CreateSchema` emits the right DDL either way and stays idempotent, but — like
everything else it does — it will not retype a table that already exists. Choose
before the tables are created, or retype the columns in your own migration.

## The live test lane

A live end-to-end suite sits behind a build tag, so the default `go test ./...`
stays database-free:

```sh
AUTHLAYER_TEST_DSN='postgres://user:pass@host/scratch?sslmode=disable' go test -tags integration ./store/drops/
```

<Warning>
**This lane is destructive and wants the database to itself.** It `DROP`s the
auth, RBAC, invite, service-account and identity tables in the target database
on the way in and rebuilds them, so point `AUTHLAYER_TEST_DSN` at a scratch database, never at
anything you care about.

It also expects **exclusive** use of it: two copies running at once — or
anything else writing those tables — will fail each other in ways that look like
product bugs (`relation ... does not exist` mid-run, timing measurements
polluted by the other client's writes).
</Warning>
