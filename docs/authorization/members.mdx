---
title: "Managing members"
description: "Adding, promoting, removing, leaving and transferring ownership — what each call requires, and the one that moves less than you expect."
---

Every call on this page reads the acting subject and the active scope from the
[context](/concepts/context). None of them takes an actor argument.

| Call | Requires | Notes |
|---|---|---|
| `CreateOrganization(ctx, name, slug)` | subject only | caller becomes owner; **no permission check** — gate it upstream |
| `AddMember(ctx, userID, roleKey)` | `member:create` + escalation guard | `ErrAlreadyMember` on a duplicate |
| `ChangeMemberRole(ctx, userID, roleKey)` | `member:update` + escalation guard | owner cannot be demoted under `LastOwnerLocked` |
| `RemoveMember(ctx, userID)` | `member:delete` + escalation guard **on the target's role** | see [what that does and does not stop](#the-guard-runs-on-the-target-s-role) |
| `LeaveContainer(ctx)` | membership only | owner cannot leave under `LastOwnerLocked` |
| `ListMembers(ctx)` | membership only | non-members get `ErrNotMember`, not an empty list |
| `TransferOwnership(ctx, userID)` | **owner only** | target must already be a member |

<Note>
`CreateOrganization` performs no permission check because there is no container
yet to check against. Whether a given user may create an organization at all is
your application's decision, and it belongs upstream of this call.
</Note>

## A worked sequence

{/* verify:import */}
```go
import (
	"context"
	"errors"
	"fmt"
	"sort"

	"github.com/bernardoforcillo/authlayer/access"
	"github.com/bernardoforcillo/authlayer/org"
	"github.com/bernardoforcillo/authlayer/store/memory"
)
```

{/* verify:main */}
```go
svc := org.New(org.NewAccess(map[string][]access.Action{
	"project": {"create", "read", "update", "delete"},
}), memory.New[org.Organization, org.Member]())

alice := org.WithSubject(context.Background(), "alice")
acme, _ := svc.CreateOrganization(alice, "Acme", "acme") // alice is owner
ctx := org.WithOrg(alice, acme.ID)

_, err := svc.AddMember(ctx, "bob", org.RoleAdmin)
fmt.Println("add bob as admin:", err)

_, err = svc.AddMember(ctx, "bob", org.RoleMember)
fmt.Println("add bob twice:", errors.Is(err, org.ErrAlreadyMember))

fmt.Println("promote carol, who is not a member:",
	errors.Is(svc.ChangeMemberRole(ctx, "carol", org.RoleAdmin), org.ErrNotMember))

members, _ := svc.ListMembers(ctx)
fmt.Println("members:", len(members))
```

```
add bob as admin: <nil>
add bob twice: true
promote carol, who is not a member: true
members: 2
```

## The guard runs on the target's role

`RemoveMember` resolves the **target's** role and refuses if it grants anything
the actor lacks. That is what stops a mid-level administrator from evicting
someone above them.

{/* verify:main */}
```go
// A custom role that can manage members but knows nothing about projects.
_, _ = svc.CreateRole(ctx, "moderator", "Moderator", map[string][]access.Action{
	org.ResourceMember: {org.ActionCreate, org.ActionDelete},
})
_, _ = svc.AddMember(ctx, "erin", "moderator")
_, _ = svc.AddMember(ctx, "carol", org.RoleMember)

erin := org.WithOrg(org.WithSubject(context.Background(), "erin"), acme.ID)

// carol's role grants nothing, so it is a subset of erin's: allowed.
fmt.Println("moderator removes a plain member:", svc.RemoveMember(erin, "carol"))

// bob is an admin, which grants far more than moderator: refused.
fmt.Println("moderator removes an admin:",
	errors.Is(svc.RemoveMember(erin, "bob"), org.ErrPrivilegeEscalation))
```

```
moderator removes a plain member: <nil>
moderator removes an admin: true
```

<Warning>
**Equal power is allowed.** The test is `target.SubsetOf(actor)`, and a set is a
subset of itself — so one `admin` **can** remove another `admin`, and two
holders of the same custom role can remove each other. The guard refuses only a
target who holds something the actor does not.

`EscalationAllowEqual` is a declared `EscalationMode`, but it currently behaves
exactly like `EscalationStrict`; it is reserved for future strictly-less
semantics. There is no mode today that refuses an equal-power removal.
</Warning>

{/* verify:main */}
```go
bob := org.WithOrg(org.WithSubject(context.Background(), "bob"), acme.ID)
_, _ = svc.AddMember(ctx, "dana", org.RoleAdmin)
fmt.Println("admin removes an equal admin:", svc.RemoveMember(bob, "dana"))
```

```
admin removes an equal admin: <nil>
```

If your application needs strict seniority between peers, model it as distinct
roles with distinct grants rather than expecting the guard to separate two
holders of the same one.

## The last owner is locked

With `Policy.LastOwnerLocked` on — the default — the owner cannot be removed,
demoted, or leave. Ownership still moves, through `TransferOwnership`.

{/* verify:main */}
```go
fmt.Println("demote the owner:",
	errors.Is(svc.ChangeMemberRole(ctx, "alice", org.RoleMember), org.ErrLastOwner))
fmt.Println("owner leaves:", errors.Is(svc.LeaveContainer(ctx), org.ErrLastOwner))
```

```
demote the owner: true
owner leaves: true
```

<Note>
The owner check runs **before** the escalation guard in `RemoveMember`, so an
attempt to remove the owner is `ErrLastOwner` rather than
`ErrPrivilegeEscalation`, whoever asks.
</Note>

## `TransferOwnership` moves less than you expect

<Warning>
It moves `owner_id` and **nothing else**. Neither membership's role key
changes, so the outgoing owner keeps whatever role they were stored with —
typically `owner`, which is a full role and therefore still elevated. Demote
them afterwards, as the new owner, if that is not what you want.
</Warning>

{/* verify:main */}
```go
fmt.Println("transfer to bob:", svc.TransferOwnership(ctx, "bob"))

after, _ := svc.Container(ctx, acme.ID)
fmt.Println("owner is now bob:", after.OwnerID == "bob")

roster, _ := svc.ListMembers(ctx)
sort.Slice(roster, func(i, j int) bool { return roster[i].UserID < roster[j].UserID })
for _, m := range roster {
	fmt.Println(" ", m.UserID, "holds", m.RoleKey)
}
```

```
transfer to bob: <nil>
owner is now bob: true
  alice holds owner
  bob holds admin
  erin holds moderator
```

<Note>
`ListMembers` returns the container's memberships in **no specified order** —
the port does not promise one, and `store/memory` iterates a map. Sort before
you render, as the snippet above does.
</Note>

The target must already be a member; `TransferOwnership` admits nobody. Only
the current owner may call it — no permission grant substitutes, not even a
full one (`ErrOwnerOnly`).

## Admitting someone with no standing yet

`AddMember` requires an actor who already holds `member:create`. To admit
someone who has no relationship with the container yet — a person you know only
by email address — use [invitations](/invitations/overview), which end at
`GrantMembership` rather than `AddMember`.
