title: "Integrity and retention"
description: "Crash recovery, a per-topic daily hash chain, verification that names what was rewritten, and retention that marks seals purged before it deletes — so Verify never raises a false alarm."
---

The `Store` never rewrites an event, and deletes one only through retention.
That is a promise of the *port*. What lets you **prove** it afterwards is the
seal.

{/* verify:import */}
```go
import (
	"context"
	"crypto/sha256"
	"encoding/hex"
	"encoding/json"
	"fmt"
	"time"

```

```go
clock := time.Date(2026, 3, 1, 9, 0, 0, 0, time.UTC)
store := memory.NewAuditStore()
svc := audit.New(store,
	audit.WithRuntime(core.Runtime{Clock: func() time.Time { return clock }}),
	audit.WithTopics(audit.Topic{Key: "menus", Retention: 30 * 24 * time.Hour}))
ctx := context.Background()
actor := audit.Actor{Type: audit.ActorUser, ID: "alice"}

// Day one: one event that finishes, one whose process dies mid-action.
_, _ = svc.Record(ctx, audit.Event{Topic: "menus", Action: "menu.create", Origin: "backend",
	Actor: actor, Outcome: audit.OutcomeOK})
crashed, _ := svc.Begin(ctx, audit.Event{Topic: "menus", Action: "menu.delete", Origin: "backend", Actor: actor})

clock = clock.Add(26 * time.Hour) // the next day

// A day holding an open event cannot be sealed.
_, err := svc.Seal(ctx, clock)
fmt.Println("seal with an open event:", err != nil)

// Reconcile closes it as unknown.
n, _ := svc.Reconcile(ctx, time.Hour)
closed, _ := svc.Get(ctx, crashed.ID)
fmt.Println("reconciled:", n, closed.Outcome, closed.Reason)

seals, _ := svc.Seal(ctx, clock)
fmt.Println("sealed days:", len(seals), "events in the first:", seals[0].EventCount)

report := func() {
	statuses, _ := svc.Verify(ctx, []string{"menus"}, seals[0].Day, seals[0].Day)
	fmt.Println("verify:", statuses[0].State, statuses[0].Detail)
}
report()

// Retention outlives the seal, not the other way round.
clock = clock.AddDate(0, 0, 60)
deleted, _ := svc.ApplyRetention(ctx)
fmt.Println("retention deleted:", deleted["menus"])
report()
```

<Note>
The IP address and user agent of an event are **not** part of its hash: they are
personal data that [clear on their own, shorter schedule](/audit/personal-data#a-shorter-retention-for-client-data),
and a seal that covered them would call every scrub a tampering. Everything else
about an event is covered.
</Note>

## Reconcile

`Begin` stores an event before the action runs; if the process dies, the
completion never arrives. `Reconcile(ctx, olderThan)` closes every open event
that began more than `olderThan` ago with `OutcomeUnknown` and
`Reason: "reconciled"`, and returns how many it closed. Choose an `olderThan`
longer than any action can run. It is safe on several replicas at once: an
event another replica completed first is skipped.

It exists because a seal needs a finished day: **a day with an open event is not
sealed** (`ErrOpenEvents`). The other topics are sealed regardless and the
errors are joined, so one stuck topic never holds back the rest.

## Seal

`Seal(ctx, until)` seals, for every declared topic, each UTC day that ended at
or before `until` and has no seal yet, oldest first. Each seal carries the
day's event count and first/last `Seq`, a SHA-256 over the day's canonical
events, and a `SealHash` that chains the **previous day's** seal. Empty days are
sealed too, so removing a whole day is detected.

Run it on a schedule — hourly is fine. `until` is capped at the start of the
`Service` clock's current day, so a day that has not ended on this replica's
clock is never sealed, whatever you pass. Several replicas may run it at once:
a day another replica sealed first is skipped, and the chain continues from
that seal. Once a day is sealed the `Store` refuses a new event in it
(`ErrSealed`).

An event stamped just before midnight can still be on its way to the store when
its day is sealed. The store then refuses the seal as stale (`ErrSealStale`) and
`Seal` digests the day again, so the seal covers the event; an insert that
arrives after the seal instead fails with `ErrSealed`, and its action with it.
Passing a `until` a few minutes in the past — `Seal(ctx, time.Now().Add(-10*time.Minute))`
— leaves such stragglers time to land first. The chain of a new topic starts at
the earliest day any of its events occurred on.

<Note>
`Seq` is increasing, not gapless: a backend may consume a value on a duplicate
or refused insert. A hole in `Seq` is therefore **not** evidence of a deletion.
The seals are.
</Note>

## Verify

`Verify(ctx, topics, from, to)` returns one `DayStatus` per topic and UTC day:

| State | Meaning |
|---|---|
| `ok` | the day's events hash to its seal, which links to the previous day's |
| `mismatch` | something no longer matches; `Detail` says what |
| `unsealed` | no seal covers the day yet |
| `purged` | retention deleted the events; the seal still links and was marked purged only once the day was past its topic's retention |

A `mismatch` names the check that failed: `events_hash` (an event was altered,
inserted or deleted, or a stored event is unreadable), `seal_hash` (the seal row
itself was edited, its first/last `Seq` included), `chain` (the seal no longer
links to the previous one, or a day between two seals lost its own — a day was
deleted or replaced), or `purged_early` (the seal was marked purged
while the day was younger than its topic's retention, so its events went
outside retention). Editing a seal to match an edited event does not help: the
next day's `PrevHash` no longer matches.

## The hash format

The hashes are computed by the `Service`, in Go, from what the store returns, so
every store produces the same ones and an outside verifier can recompute them.

- **Canonical row.** Each event is one JSON object with exactly these keys, in
  this order: `id`, `seq`, `occurred_at`, `completed_at`, `topic`, `action`,
  `source`, `origin`, `procedure`, `actor_type`, `actor_id`, `actor_display`,
  `on_behalf_of`, `session_id`, `container_id`, `resource_type`, `resource_id`,
  `outcome`, `code`, `reason`, `request`, `changes`, `client_time`,
  `duration_ms`. An empty string field is `""`; only `completed_at`,
  `client_time`, `request` and `changes` are ever `null`. Times are UTC in
  RFC 3339 with the fraction's trailing zeros dropped (Go's `time.RFC3339Nano`:
  `2026-03-01T09:00:00Z`, `2026-03-01T09:00:00.5Z`). `request` and `changes`
  are re-encoded with sorted keys and no whitespace, numbers spelled as the
  store returns them. The encoding is Go's `encoding/json`, which escapes `<`,
  `>` and `&` as `\u003c`, `\u003e` and `\u0026`. The IP address and user agent
  are not part of it.
- **`events_hash`** = hex SHA-256 of the day's canonical rows in `Seq` order,
  each followed by `\n`. An empty day hashes the empty string.
- **`seal_hash`** = hex SHA-256 of `prev_hash|topic|day|event_count|events_hash`,
  with `day` as `YYYY-MM-DD` and `event_count` in decimal. A topic's first seal
  has `prev_hash = ""`.

{/* verify:main */}
```go
at := time.Date(2026, 3, 1, 9, 0, 0, 0, time.UTC)
s2 := audit.New(memory.NewAuditStore(),
	audit.WithRuntime(core.Runtime{Clock: func() time.Time { return at }, IDs: func() string { return "e1" }}),
	audit.WithTopics(audit.Topic{Key: "t"}))
_, _ = s2.Record(ctx, audit.Event{Topic: "t", Action: "menu.create", Origin: "backend",
	Actor: audit.Actor{Type: audit.ActorUser, ID: "alice"}, Outcome: audit.OutcomeOK,
	Request: json.RawMessage(`{"b": 1, "a": "x"}`)})
at = at.Add(24 * time.Hour)
day1, _ := s2.Seal(ctx, at)

row := `{"id":"e1","seq":1,"occurred_at":"2026-03-01T09:00:00Z","completed_at":"2026-03-01T09:00:00Z",` +
	`"topic":"t","action":"menu.create","source":"server","origin":"backend","procedure":"",` +
	`"actor_type":"user","actor_id":"alice","actor_display":"","on_behalf_of":"","session_id":"",` +
	`"container_id":"","resource_type":"","resource_id":"","outcome":"ok","code":"","reason":"",` +
	`"request":{"a":"x","b":1},"changes":null,"client_time":null,"duration_ms":0}`
eh := sha256.Sum256([]byte(row + "\n"))
eventsHash := hex.EncodeToString(eh[:])
sh := sha256.Sum256([]byte("" + "|" + "t" + "|" + "2026-03-01" + "|" + "1" + "|" + eventsHash))
fmt.Println("events_hash:", eventsHash == day1[0].EventsHash, "seal_hash:", hex.EncodeToString(sh[:]) == day1[0].SealHash)
```

`first_seq`, `last_seq`, `sealed_at` and `purged_at` are stored beside the
hashes but are not part of them; `Verify` checks the first two against the
events and `purged_at` against the topic's retention.

## Retention

Each topic keeps its events for `Topic.Retention`, falling back to
`WithDefaultRetention` (one year by default). `ApplyRetention(ctx)` deletes, per
topic, what is older, and returns the count per topic. Two rules keep it from
undermining the thing it sits next to:

- **Only sealed days are purged.** A topic with no seal keeps everything, so an
  event is never deleted before the seal that covers it exists.
- **Seals are marked purged before their events go**, in that order. `Verify`
  then reports the day as `purged` instead of finding events missing from a
  seal that thinks it still has them. The seals themselves stay forever.

Run `ApplyRetention` on a schedule too — after `Seal`, so the days it may purge
are sealed.

`Verify` checks a purged day against its topic's **current** retention: a seal
marked purged while the day was younger than that is `purged_early`. Shortening
a retention is therefore safe; lengthening one makes the days purged under the
shorter value read as `purged_early`, so review them when you do.
