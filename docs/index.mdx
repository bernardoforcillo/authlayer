authlayer is a Go **library**. You import it, hand it a store, and call it from
your own handlers. It gives you two halves that share nothing but a user id
string:

```sh
go get github.com/bernardoforcillo/authlayer
```

Requires **Go 1.26+**. The current release is **v0.1.0**.

## What authlayer is not

This is the misconception worth clearing first, because it decides how much of
your application authlayer replaces:

<AccordionGroup>
  <Accordion title="It is not an HTTP server, a middleware, or a CLI" icon="server">
    There are no handlers, no cookies, no middleware, no base URL, and no
    binary to run. Every method takes a `context.Context` and returns values.
    Your application owns transport entirely — which route, which status code,
    which cookie flags, which session storage on the browser side.
  </Accordion>
  <Accordion title="It does not send email" icon="envelope">
    `SignUp`, `RequestPasswordReset`, `RequestEmailChange` and
    `InviteByEmail` each return a plaintext token **exactly once**. Turning
    that into a message — which template, which link, which provider — is
    yours. authlayer knows no base URL.
  </Accordion>
  <Accordion title="It does not own your user profile" icon="user">
    The authentication half persists `auth.UserBase` and nothing else: an id,
    a normalized email, a verification stamp, a password hash, timestamps.
    A `DisplayName` or `Plan` field lives in your own table, keyed by
    `UserBase.ID`. That is what keeps authlayer's migrations from ever owning
    a column your product's shape decides.
  </Accordion>
  <Accordion title="It does not run the OAuth dance, or store a provider's tokens" icon="right-to-bracket">
    [External identities](/oauth/overview) are shipped — "sign in with
    Google/GitHub/…", linked to a local account. But authlayer never redirects a
    browser, never exchanges an authorization code, and is not an API client:
    you run the dance and hand over the result. An identity row holds
    `(provider, subject, email)` and two timestamps, with **no token column** of
    any kind.
  </Accordion>
</AccordionGroup>

<Note>
The authorization half stores **no users at all** and declares no foreign key
to yours. A user id is a value it carries, never one it validates against a
schema of its own. You can adopt `scope`/`org` on top of an existing user
table and change nothing about how your accounts work.
</Note>

## The dependency budget

Three requirements, and which one you pay depends on what you import:

| Package | Pulls in |
|---|---|
| `access`, `token` | standard library only |
| `password`, and so `auth` | `golang.org/x/crypto` — bcrypt only |
| `scope`, `org`, `team`, `invite` | `github.com/bernardoforcillo/drops` |
| `store/drops` | `github.com/jackc/pgx/v5` |

The UUIDv7 generator behind every id authlayer mints is written out in
`internal/uid` rather than depended on, which is what keeps that list at three.
